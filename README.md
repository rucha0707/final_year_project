
# Synapse-Connect: A Neuromuscular Integration

### An EEG–EMG-Based Intelligent System for Real-Time Robotic Hand Control

Synapse-Connect is a biosignal-processing and machine-learning project that explores the integration of human neural and muscular signals with robotic movement. The system uses Electroencephalography (EEG) and Electromyography (EMG) signals to identify movement-related activity and muscle gestures, process them using machine-learning models, and translate predictions into commands for a servo-controlled robotic mechanism.

The project combines biomedical signal acquisition, signal processing, machine learning, embedded systems, and real-time hardware control to investigate a more intuitive approach to human–robot interaction.

## Project Overview

Traditional robotic control systems often rely on switches, joysticks, or predefined commands. Synapse-Connect explores an alternative by using physiological signals generated by the human body.

The project investigates two complementary signal modalities:

- **Electromyography (EMG):** Measures electrical activity produced by muscles and is used to classify hand gestures such as hand opening and hand closing.
- **Electroencephalography (EEG):** Records electrical activity from the scalp and is used to investigate movement-related activity, distinguishing movement from rest.

Python-based processing and machine-learning models interpret the acquired signals. The resulting commands are communicated to an Arduino microcontroller, which controls servo motors to execute the corresponding robotic movement.

The project includes separate EEG and EMG processing workflows, with hardware integration forming the basis for the broader neuromuscular control system.

## Objectives

1. Acquire EEG and EMG signals using biosignal acquisition hardware.
2. Develop labelled datasets containing resting, movement-related, and muscle-gesture recordings.
3. Preprocess noisy biosignals and extract meaningful signal features.
4. Train machine-learning models for EMG gesture classification and EEG movement detection.
5. Implement real-time signal processing and prediction using Python.
6. Establish serial communication between Python and an Arduino microcontroller.
7. Translate model predictions into servo motor movements.
8. Evaluate classification performance and investigate improvements in multi-class gesture recognition.

## Working Methodology

### 1. Biosignal Acquisition

EEG and EMG recordings are collected from participants using the corresponding electrode and acquisition setups.

- EMG recordings capture muscle activation during different hand gestures.
- EEG recordings capture brain activity during rest and attempted or intended movement.

Recordings are labelled according to the activity performed so that supervised machine-learning models can learn the patterns associated with each class.

### 2. Signal Preprocessing

Physiological signals are susceptible to electrical interference, movement artefacts, and variations between participants.

The preprocessing pipeline divides continuous signals into smaller windows and prepares them for feature extraction and classification.

### 3. Feature Extraction

The project explores features that summarize signal amplitude, variation, and frequency characteristics.

**Time-domain features:**

- Mean Absolute Value (MAV)
- Root Mean Square (RMS)
- Signal variance and standard deviation
- Integrated EMG (IEMG)
- Waveform length
- Zero-crossing count

**Frequency-domain features:**

- Spectral power
- Frequency-band power
- Other frequency-based statistical features, where applicable

The actual feature set depends on the signal modality and the trained model. Training and real-time inference must use identical feature definitions and ordering.

### 4. Model Prediction

The extracted features are passed to the appropriate trained model. The model predicts the corresponding gesture or movement state.

### 5. Hardware Execution

Python communicates the predicted command to the Arduino through serial communication. The Arduino interprets the command and drives the servo motors to perform the associated movement.

## EMG Gesture Recognition

The EMG pipeline focuses on identifying hand gestures from muscle electrical activity.

### Gesture Classes

| Class | Gesture |
|---|---|
| 0 | Hand Open |
| 1 | Hand Close |
| Additional class | Experimental third movement, subject to validation |

The primary classifier uses a **Random Forest Classifier** to distinguish hand-open and hand-close activity.

The project investigates recordings from the biceps and brachioradialis muscles. These muscles provide information about upper-limb muscle activation, although electrode placement and the selected gestures must be considered when interpreting classification results.

### EMG Processing Workflow

1. Acquire EMG signals from the selected muscle channels.
2. Divide the signals into fixed-length windows.
3. Extract relevant signal features.
4. Apply the same preprocessing used during model training.
5. Pass the feature vector to the trained classifier.
6. Generate the predicted gesture label.
7. Send the corresponding control command to the Arduino.

The documented configuration uses a sampling rate of approximately **500 Hz**, with **500-sample windows and 250-sample overlap**.

### Multi-Class Gesture Recognition

An additional movement was investigated to expand the system beyond hand opening and closing. Introducing a third class reduced the reported classification accuracy to approximately **71%** in the experimental configuration discussed during development.

This result highlights the challenges of classifying multiple movements using overlapping muscle-activation patterns.

Potential improvements include:

- Feature engineering and selection.
- Hyperparameter tuning.
- Improved electrode placement.
- Better class balance.
- More representative participant recordings.
- Evaluation using unseen participants.

The final reported accuracy should reflect the validated evaluation of the model being presented.

## EEG-Based Movement Detection

The EEG pipeline investigates movement-related brain activity and distinguishes movement from rest.

### Classification Labels

| Label | State |
|---|---|
| 0 | Rest |
| 1 | Movement-related activity / movement intention |

The EEG workflow uses a separate trained model and scaler rather than assuming that the EMG classifier can process EEG signals directly.

### EEG Processing Workflow

1. Acquire EEG data using the biosignal acquisition hardware.
2. Divide continuous recordings into fixed-length windows.
3. Calculate relevant spectral and band-power features.
4. Apply the preprocessing and scaling used during training.
5. Predict the movement-related state.
6. Communicate the appropriate command to the Arduino.
7. Execute the configured servo response.

The documented EEG configuration uses a sampling rate of **256 Hz** and **512-sample windows**, corresponding to two seconds of data, with overlapping windows.

EEG movement detection is sensitive to noise, electrode contact, individual differences, and the distinction between actual movement, attempted movement, and movement intention.

Reliable real-time implementation therefore requires consistent preprocessing and windowing between training and deployment.

## Dataset and Preprocessing

The project involves participant-based biosignal collection, with separate datasets for EMG and EEG.

### EMG Dataset

- Labelled recordings for hand opening and hand closing.
- Recordings from multiple participants.
- Two muscle-signal channels in the documented configuration.
- Window-based segmentation and feature extraction.
- Analysis of signal averages, variability, and differences between gesture classes.

### EEG Dataset

- Recordings representing rest and movement-related activity.
- Window-based segmentation.
- Spectral and band-power feature extraction.
- Separate model training and evaluation.

### Data Preparation Considerations

- Check for missing values and corrupted recordings.
- Verify that labels correspond to the recorded activities.
- Check class balance before training.
- Maintain consistent sampling rates, window sizes, and feature definitions.
- Keep training and test data separate to prevent data leakage.
- Evaluate generalization across participants rather than relying exclusively on randomly split windows from the same recordings.

Final participant counts, recording durations, and train/test splits should be documented using the actual dataset used for evaluation.

## Machine Learning

### Random Forest Classifier

Random Forest is the primary classifier used in the EMG hand-gesture recognition workflow.

It combines predictions from multiple decision trees and can model nonlinear relationships between extracted signal features.

The model provides a useful baseline for gesture recognition because it works with structured numerical features and can be evaluated using standard classification metrics.

### Model Evaluation

Model performance should be evaluated using:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix

For multi-class classification, per-class precision and recall are particularly important because overall accuracy can hide poor recognition of individual gestures.

Potential comparison models include:

- Support Vector Machine (SVM)
- XGBoost
- K-Nearest Neighbours (KNN)
- Multi-Layer Perceptron (MLP)

These are candidate models for experimentation rather than claims that every model has already been implemented.

## Robotic Control and Integration

The hardware integration connects software predictions to physical movement.

### Communication Workflow

1. Python loads the trained model and associated preprocessing objects.
2. Biosignal data is acquired and processed in real time.
3. The model produces a gesture or movement-state prediction.
4. Python sends the corresponding command through the serial interface.
5. Arduino receives and interprets the command.
6. The servo motor moves according to the configured control logic.

### Rest-State Behaviour

The controller should distinguish between a detected movement and the absence of a reliable movement command.

When no valid command is detected, the robotic mechanism should remain in, or return to, its configured resting position as appropriate.

The precise servo angles, serial command format, Arduino pin assignments, and motor power arrangement depend on the final hardware implementation.

**Important:** A model prediction does not automatically guarantee physical movement. Signal classification, serial communication, servo power, wiring, and mechanical constraints must all function correctly for the complete system to work.

## Challenges and Limitations

### 1. Biosignal Variability

Muscle and brain signals vary between individuals, sessions, electrode positions, and levels of muscle activation.

### 2. Multi-Class Classification

Adding gesture classes can increase overlap between feature distributions and reduce classification accuracy.

### 3. Real-Time Prediction

Window size and overlap influence response latency. Training and inference must use compatible preprocessing configurations.

### 4. False-Positive Movement Detection

Noise and physiological artefacts can produce incorrect movement predictions, particularly in EEG-based detection.

### 5. Hardware Integration

Serial communication delays, servo power requirements, electrical noise, and mechanical limitations can affect the complete system.

### 6. Participant Generalization

A model that performs well on recordings from a known participant may not perform equally well on a new participant. Testing on unseen participants is important for evaluating generalization.

### 7. EEG–EMG Integration

EEG and EMG measure different physiological phenomena and require different preprocessing pipelines. Combining them into a unified control strategy requires synchronization, integration logic, and independent evaluation.
